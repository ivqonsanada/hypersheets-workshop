# Haiku trial, 2026-11-15

Can Claude Code on Claude Haiku 5.5 alone, with this plugin, make a decent 15 to 30 second motion video of a learner's page? Each run was a real headless Claude Code session, asked the way a learner would ask, then rendered, looked at frame by frame, and scored against the rubric below.

**Result.** Yes. On the round 4 harness (commit `319712c`), 5 of 5 consecutive Haiku runs passed the rubric (runs 9 to 13), 4 of them with no quality note; counting from the first run the harness let through, 10 of 10 passed (runs 4 to 13). A finished video cost **$0.0177 on average** (from $0.0165 to $0.0190), about 33 turns and 1.5 minutes of the session, the render included. With every trial call counted, probes and harness failures too, 15 calls cost $0.19, or $0.019 per finished video.

**Round 5 (the same day, later).** The skill gained a telemetry step and a new shortening rule (cut a long line before a joining word). 7 more runs, 7 passes: on Maya's page the awkward cut of runs 6 and 13 did not come back (4 of 4 clean), and a new page full of over-long lines passed 3 of 3. At $0.0182 per video on average, the extra step costs about $0.0005. The Workshop promo made with the same harness is under [The Workshop promo](#the-workshop-promo).

**Round 6 (template v2, later still).** The template was rebuilt to look like a motion designer's work with the same 13 slots: the name on a band of the page's own colour, the real page in a large window where a pixel marker finds the name and then the list, the list landing out of that marker, and an end card in the page's colour. Haiku sets no colour; the video reads it from the page. 6 more runs, 6 passes, the last 3 on the final template, where each scene's motion sits in its own `.js` file so Haiku reads only text and styles. On that template a video costs $0.0181 on average, the same as v1 ($0.0182); with the motion inside the scene files it had cost $0.0209. Draft render time is unchanged (30 to 33 s, v1 32 s). Tagged `v0.2.0` locally, not pushed. Details under [Round 6](#round-6-template-v2).

**Round 7 (the same evening).** The scroll stops in scene 2 no longer cut a line of text at the window's edges: on all seven pages both stops rest between lines, Boni's and the Workshop page's descenders included, and `check` still passes on all seven. The skill's checklist now says what the 6 s and 9 s frames should show. Two Haiku runs on the final skill passed (Dimas and Boni, $0.017 each), both describing those frames right. `v0.2.0` moved to the round's last commit, still local. Details under [Round 7](#round-7-clean-scroll-stops).

## How a run works

- `dev/run-trial.sh <run-dir> <fixture> <prompt> [max-turns]`, one at a time through the machine's heavy-job lock.
- `claude -p --model claude-haiku-5-5 --output-format stream-json --verbose --restricted --strict-mcp-config --plugin-dir <a copy of this repo>`. Stream-json instead of json so a failed run shows which tool calls went wrong; its last line is the same result object `--output-format json` prints (`usage`, `total_cost_usd`). Restricted mode loads no user, project or local settings files (so no personal CLAUDE.md, skills or hooks) and keeps the file tools inside the run folder. The first probe confirmed it: the session saw only Claude Code's built-in skills, this plugin's `video-promo`, and no MCP server; asked whether its instructions mention /compact (the owner's CLAUDE.md does), it said no.
- Permission prompts go to `dev/learner-mcp.mjs` (`--permission-prompt-tool`), a stand-in that answers as the track's guide tells a learner to: yes to copying the template and the page into `video/`, yes to looking around, no to anything else. Every prompt is logged to the run's `prompts.jsonl`. In the passing runs it was asked about once per run (the `cp -R` of the template); twice it said no to a command holding a dollar sign, and Haiku used its own Grep tool instead.
- Tools: Bash, Read, Write, Edit, Glob, Grep, Skill. Bash allowed only for `npx hyperframes@0.9.51`, `cp`, `ls`, `mkdir`, `node`.
- The working folder is a copy of a fixture page, as a learner's `my-page` folder from track 2. Five fixtures: Rina (Indonesian, `aku`, light serif page), Dimas (English, dark page), Maya (Indonesian, `saya`, white card page), Boni (Indonesian, `saya`, no learning list, a 95-character role, a local photo and a CSS file) and Siti (English, never seen while tuning, long role and three list lines all over the limit). Round 5 added Nadia (Indonesian, `aku`, a header band; a 66-character role and three list lines of 49 to 61 characters, each with a joining word: `untuk`, `yang`, `supaya`).
- The machine's Claude login pays (subscription). `total_cost_usd` in the JSON result is what the same tokens would cost on the API.
- From round 5, each run has its own HyperFrames settings folder (`HYPERFRAMES_CONFIG_DIR=<run>/hf-config`, starting with telemetry on, as on a fresh machine), so the skill's `telemetry disable` never changes this laptop's own setting (still on, used by other work) and no credential file is copied. `HYPERFRAMES_NO_TELEMETRY=1` is set as a safety net. Runs 1 to 13 ran before this and sent HyperFrames' usage events from this laptop.

## Rubric

A run passes when every item passes.

| # | Item | How it is judged |
|---|---|---|
| R1 | Renders without errors | `video/promo.mp4` exists and plays; `check` shows no errors |
| R2 | Under 30 s | ffprobe duration between 15 and 30 s |
| R3 | Readable at phone size | no text under 32 px in the 1080 px frame (the template's sizes are 36 to 120 px; any change to a locked style fails this), the stills read at 270 px wide |
| R4 | Nothing off-screen | no word cut at an edge or covered, in eight stills from the rendered MP4 |
| R5 | Smooth timing | locked timing unchanged, no blank or broken scene, the real page shows in scene 2 |
| R6 | Matches DESIGN.md | locked styles unchanged (warm dark ground, two accents, Finlandica, pixel marks), no emoji, no gradient |
| R7 | True and finished | every slot filled, no `TODO-`, names and address as on the page, nothing invented, the page's language |

From round 6 (template v2), R3's sizes are 36 to 176 px and R6 names v2's locked look; see [Round 6](#round-6-template-v2).

Also recorded, not required: whether Haiku looked at the frames (`video/frames/`, `video/REVIEW.md`), turns, minutes, tokens and cost.

## What changed in the harness each round

**Before any Haiku run** (checked by hand on two filled copies, one with every slot at its limit):
- The template moved from one file to one sub-composition per scene, because `check` warned five times that a single-file root should be split, and a small model chases warnings.
- Text stays inside x 120 to 940 and carries `data-layout-allow-safe-zone`: the social safe areas HyperFrames checks (TikTok, Reels, Shorts) leave a band about 660 px wide and end at 65% of the height, which conflicts with DESIGN.md ("the scene uses that height"). With the attribute the check is silent about them; the text still sits inside the 80% title-safe box.
- The name dropped from 128 to 120 px and the cursor moved out of the name's line, after the limit test broke "Bartholomeus" in the middle of the word.
- The window opens from the top (the address bar first), not from the bottom.
- The placeholder page says PAGE MISSING in English, so the English guide can name it.
- Result: `check` shows one warning, `film_silent`, which the skill names as intended.

**Round 1 (runs 1 to 3, harness only).** Headless Claude Code cannot have a person approve the flagged `cp -R` that copies the template; no allow rule covers it. The trial got a stand-in for the learner (`dev/learner-mcp.mjs`, via `--permission-prompt-tool`) that says yes to what the guide tells a learner to approve (copy the template into `video`, copy the page into `video/assets/page`, look around) and no to anything else, and logs every prompt. Each run also gets its own copy of the plugin, so Haiku can never change the source template. In the skill: one command per Bash call, so every prompt a learner sees is one readable action.

**Round 2 (runs 4 to 6).** No skill change was needed for the video itself: three passes on three different pages. Run 6 showed two quality gaps the rubric did not catch.

**Round 3 (runs 7 and 8).** The slot table gives Indonesian texts for both voices, `aku` and `saya`, and says to use the page's own. A long page line is cut to its main idea in a correct sentence, with an example of what not to do. A fourth, harder fixture joined: Boni, a `saya` page with no learning list (the fallback), a 95-character role line, a local photo and a separate CSS file (both must be copied for scene 2 to look right).

**Round 4 (runs 9 to 13).** The shortening example in the skill was taken from the Maya fixture, and run 8 copied it word for word; it is now an example that appears on no fixture. A fifth fixture nobody had tuned for joined: Siti, an English page with a header band, an 89-character role and three list lines all longer than their 40-character slot. Nothing else changed, and the five runs below all ran on this exact plugin (commit `319712c`).

**Round 5 (runs 14 to 20, the final harness: commits `00772b6` and `9e4b6aa`).** Two skill changes, tested together:
- *Telemetry.* A new step 5 runs `npx hyperframes@0.9.51 telemetry disable` before any other HyperFrames command (the README says why a one-time command and not an environment prefix). In all 7 runs it was the first HyperFrames command, and the run's own settings file ended with telemetry off. No prompt reached the stand-in learner for it: the runner's allow rule covers `npx hyperframes@0.9.51`, as a learner's "don't ask again" would.
- *Shortening.* A long line is cut before a joining word (`yang`, `tanpa`, `dengan`, `untuk`, `supaya`, `agar`, `sambil`; `that`, `which`, `without`, `with`, `so`, `while`, `because`) and everything before it is kept word for word, or the whole line is written again; single words are never taken out of the middle. One Indonesian and one English example, neither on a fixture.
- *Runs.* Maya, the page that failed before, 4 times; Nadia, a new page built to tempt mid-line cuts, 3 times. One run of the 8 allowed was left unused.
- *Result.* 7 of 7 passed the rubric. On Maya, 4 of 4 runs cut line 3 before `tanpa` ("Menambah foto masakan"), against 2 of 4 clean before. On Nadia, 3 of 3 kept every shortened line a correct sentence; two of them (17 and 19, the same texts) took one word out of the middle of item 2 and still read naturally. The fix passes more often than the rule it replaced, so it stays.

2. ~~**Pinning.**~~ Settled. The marketplace reference ([code.claude.com/docs/en/plugins/marketplace-reference](https://code.claude.com/docs/en/plugins/marketplace-reference)) says a relative-path source, `"."` or `"./"` included, resolves from the marketplace's own files, which Claude Code has for a `github` or `git` marketplace; and that pinning the marketplace `ref` keeps refreshes on a reviewed commit, while "a plugin entry with its own remote source can still update". The loading reference says a relative-path plugin in a git-hosted marketplace is copied into the cache from that clone. Checked on Claude Code 2.1.325 with a local copy of this repo served over git HTTP: added at `#v0.1.0`, the installed skill was the tagged commit while `main` had a newer one, and `marketplace update` kept it there; added without a ref, it got `main`; after the tag was moved, a refresh followed the tag (an existing install stayed, because its version string did not change), while a marketplace added at the full commit SHA did not move. So the root layout stays and so does the guides' install line. To stop a moved tag from reaching new installs, protect `v*` tags on GitHub or give the guides the full SHA (Claude Code 2.1.324 or later).
3. **Where the track sits.** It is order 7 now, after the agent tracks. It needs only track 2's page, so it could follow track 3 (both add media to the same page).
4. **The check.** Step 5 is `url_code`: it proves the page and the code, not the video. A `url_video` check, like `url_audio` (the first `<video>` answers as video/mp4), needs a small change in the worker and the API.
5. ~~**HyperFrames telemetry.**~~ Handled: the skill runs `npx hyperframes@0.9.51 telemetry disable` before its first check, the track's step 1 has the learner run it by hand before `doctor`, step 2 lists it among the prompts (API branch `workshop-video-track`, commit `02eb56dba`), and the README explains it. ## Round 6: template v2

**Why.** The round 5 videos passed the rubric but looked plain: a near-black ground with a few grey squares, a browser frame holding a still page cut off mid-line at the bottom, a plain title. The aim was a video that looks like a motion designer made it, without making Haiku's job harder. All the design went into the template, and Haiku fills the same 13 text slots with the same limits. No slot was added.

**What the video does now** (commits `1527887`, `783d2b9` and `be5182b`):

| Time | Scene | What moves |
|---|---|---|
| 0 to 3.6 s | hello | The name is fitted as large as two lines allow (176 px down to 104) and is whole on frame 0, the cover. Within the first second a band of the page's own colour steps in behind it, one band per line with a hard shadow, and the name takes the text colour that reads on that band. A stepped curtain of the same colour rises into scene 2. |
| 3.6 to 11 s | page | The proof gets the most room (a 936 px window). The address types itself, the page loads in steps, an orange pixel marker lands on the name in the real page, the page scrolls to the list and the marker travels with it, then the marker opens out to the window's corners as the scene fades. The scroll stops are measured so the window's edges fall between lines of text; a short page does not scroll. |
| 11 to 16.6 s | learning | The list lands out of that marker. Each line's number steps in on a chip of the page's colour and its words sharpen one by one. The third chip grows into a flood of the colour. |
| 16.6 to 20 s | visit | On the page's colour: the name, the address in a pixel address bar whose caret blinks three times, the button pressed once, then two seconds still. |

- **The page's colour, with no new slot.** The page scene reads the copied page. It takes the name's colour, else the band the name sits on, else the first clearly coloured background, text or border. It skips greys and colours too close to the dark ground, and falls back to the HTML orange if nothing qualifies. It picks cream or dark text by contrast. On the fixtures: Rina brown `#7a3e12` (her name), Siti dark red `#7b2d26` and Nadia brown `#7c4a2d` (their header bands), Boni green `#3f5f45` (his name, from his CSS file), Maya yellow `#fde68a` (her tag, dark text on it), Dimas teal `#2dd4bf` (his headings), and the Workshop page its orange button. Haiku sets no colour; the skill says so in one line.
- **The ground** is afternoon light through a window: two stepped bands of flat colour that creep one step a second, in place of the five grey squares (DESIGN.md: warnet afternoons, light drawn as stepped bands, never a gradient).
- **Each scene's motion is in its own file** (`compositions/<scene>.js`, from run 24). Haiku reads the four scene files whole before editing them. With the scripts inside they were 37 KB (v1: 13 KB), and runs 21 to 23 cost more for it. Now the files it opens total 15 KB, and rule 2 says to leave `video/index.html` and the `.js` files alone.

**What it took to stay deterministic and pass `check` in HyperFrames 0.9.51** (worth knowing for later template work):
- A scene is `display: none` until its start, so a scene cannot measure itself at load: everything in it is a 0 x 0 box. The page scene measures an unseen copy of the page that it adds outside every scene (always laid out, the same 414 x 551 viewport as the window), waits for it and for its own frame, and only then registers its timeline. Every frame after that is a pure function of time.
- `check` reloads an iframe whose ancestor carries a GSAP `scale` tween (v2's first page exit was a zoom through the list) and reports the cancelled load as `request_failed`, an error. It took a bisection over eleven versions of the page scene to find; a fade on the same ancestor is fine.
- The lint rule `gsap_callback_dom_measurement` reads a one-line arrow function's body (`const f = (v) => ...;`) on to the end of the script, so a timeline callback that calls such a helper is flagged if anything later in the script measures. The helpers are function declarations.
- `data-layout-ignore` also hides an element's motion from `check`'s still-frame detector: with it on the marker, `check` reported a 4.6 s `dead_stretch` while the marker travelled. The marker no longer carries it.
- `check` measures text hidden under another element: the cream name under the band failed contrast on Maya's yellow (1.07:1), and making it transparent is `text_not_painted`, an error. Once the band has landed, the hidden name takes the band's text colour.
- Result: on all seven pages tried (the six fixtures and the Workshop page), `check` on the filled template reports only `film_silent`, as v1 did, and every text passes WCAG AA.

## Round 7: clean scroll stops

**Why the first stop cut descenders.** Measured the way the page scene measures (a 414 x 551 layout and every text line's box, in headless Chrome 148): on Boni's page the first stop left the window's bottom edge 1.00 page pixel above the bottom of a list line, and on the Workshop page 0.94. The old test called an edge clean when it fell within 1 px of a line's top or bottom, and the last pixel of a line's box is where its descenders end. Boni's page is Verdana at `line-height: normal`, where line boxes touch with no gap, so every clean edge it could find near the bottom was such a slip. The 24 px range was not the cause.

**The fix** (commit `2b5f564`, `compositions/page.js` only). The text lines become bands (lines on one row merge). An edge may sit up to 1 px into the top of a band, which is empty above the letters, and must stay half a pixel below its bottom. A stop is the point nearest to where it wants to be that keeps both edges clear (failing that, the bottom edge), 1.5 px further from the lines where the gap allows, and it may fall between whole pixels. The first stop may move down 48 page px instead of 24, never so far that the name and the marker around it leave the window. The second never pushes its heading above the window's top. Everything is still measured once, before the timeline is built, so every frame stays a pure function of time.
